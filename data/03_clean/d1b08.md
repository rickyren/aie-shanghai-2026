## The problem

Let's start with the problem statement. In the age of AI, the core problem in a data org hasn't changed; only the persona has. People double-check a weird number before it goes into a deck. Agents don't. According to a survey by VentureBeat, 57% of enterprises traced a wrong agent answer back to missing context. So we're not seeing a model problem but a context problem. 31% say it recurs, and only 17% call their AI outcomes consistently reliable. Gartner also published a study this spring saying that a robust context layer is foundational to AI success. Without it, you don't have an agent problem; you have a context problem under the hood of an agent. [seg 1687–1697]

## The AI context layer

Mechanically, this is what the AI context layer looks like. Sources on the left include warehouses, BI tools, unstructured data and documents, and the metadata graph itself. That feeds context intelligence, which generates candidate context and routes it through expert validation. So the loop is generate, validate and activate. Every piece that comes out of that carries a trust grade. [seg 1698–1703]

The context lifecycle has four parts: ingest, understand, validate, and activate. So we start with context ingestion. Enterprise context is incredibly fragmented: some of it lives in the warehouse, some of it is in BI dashboards, and some is in documents — Slack and even Google Docs, for example. We bring all of that into one unified context layer rather than asking teams to manually recreate it. Second is context intelligence, where we generate context by extracting semantic meaning from query logs, BI dashboards, and also a lot of unstructured documents. This is a continuous process that we do automatically. Third, we go into the context hub, which is a dedicated workspace for subject-matter experts to validate and also enrich data meanings. Last but not least, we move on to activating context, which unlocks semantic value wherever agents and humans work. It can be done over MCP, skills, API, SDK, and also a personalized UX. [seg 1704–1714]

## In production

We actually just graduated from a 3-month-long private and public beta into general availability. We worked closely with 30-plus customers to get them to success with DataHub's context platform. Without DataHub context, the agent often guesses and hallucinates. For instance, when a loan officer asks a Snowflake Cortex Agent, "How much is in high-risk commercial real estate loans?", it ends up picking an 80% loan-to-value threshold because it sounds plausible. The result is then only $9 million in loan value. This was confidently stated and completely wrong. With DataHub context, we retrieve the actual glossary term and realize that the LTV threshold is actually 76%, which means 6 loans at $33 million in loan value. [seg 1715–1722]

And this is what is already running in production today. At Miro, which is one of our great customers running AI with us, agent accuracy went from roughly 50% to 90% once grounded in DataHub context — that's in this chart. Another customer we love is Pinterest: the analytics agent sees 10 times the usage of the next most-used internal agent. So you're spending minutes, not hours, for a trusted answer, and that's around 70% less manual documentation work for them. At Block, agents answer metadata questions instantly over MCP. And a top-3 global bank is building a conversational text-to-SQL mobile banking agent with DataHub as the context layer underneath it. [seg 1723–1731]

## Own your business logic

Every major platform is actually building its own version of the context platform: AWS Context, Snowflake Cortex and Horizon, Databricks Unity and Genie, Microsoft Fabric IQ, Google's Knowledge Catalog, etc., etc. So we really urge all enterprises to own your own business logic. Nobody else should own what "high-risk" means at your company. You should store it in a vendor-neutral format, not locked inside one platform's layer. Buy the context infrastructure underneath it, because teams that cobble it together themselves tend to move on in a couple of quarters, and the context doesn't. So will all of your data ever live in one system? I believe the answer is really no. And that's where the value of DataHub as a vendor-neutral platform comes from. [seg 1732–1743]

I would like to end today with an analogy that we like to use internally at DataHub. We can think of the entire data estate as city streets. Some streets are on Snowflake, some are on Databricks, Oracle, and spread across unstructured data. What we provide is similar to Google Maps, allowing agents and humans to navigate all these streets. Just like traffic on Google Maps tells us which streets to avoid and which streets to take to get to our destination in the most optimized manner, we provide trust signals that allow agents to navigate the millions and thousands of datasets spread across a very fragmented data estate. Our aspiration is that we will soon see all of the work that data engineers and analysts do be entirely identified〔?〕 through autonomous agents. And that's very crucial to get a lot of enterprises up and running with trusted AI agents that matter. [seg 1744–1752]
