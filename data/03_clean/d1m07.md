## From side-by-side battles to agent evaluation

So how exactly do we evaluate model performance? For relatively simple use cases such as chat, image generation, video generation or web dev, we use side-by-side battles. Essentially, when users submit a prompt, we randomly sample two different models and put them into a battle — PK，或者说对战 — and then allow the user to vote based on the pairwise comparison. We harvest millions of these pairwise votes across all user sessions and run a statistical model to turn them into the final evaluation result. I think many of you are probably very familiar with this methodology; it was popularized by Arena a few years ago when we just started. [seg 1169–1170]

But agent evaluation poses some new challenges. Agent systems involve a lot of complex interaction between the model, the harness and the environment. The tasks are highly diverse across essentially all economic activities, and they're ever-changing. Human feedback is still a very important element in measuring agents, but it's only one piece, not the whole story. Our goal is to measure model performance on complex, long-horizon, real-world agentic tasks. So how do we do that? [seg 1171–1171]

To tackle this challenge, we developed and launched a full-fledged agentic AI product, very similar to Manus or Genspark. Users can leverage Arena's agent mode to perform a variety of agentic tasks: coding, image and video generation, research, lookup, document creation, planning, brainstorming, workflow automation and many other types of work. Arena's agent mode also supports a variety of tools, such as file editing, bash operations, web search, GitHub connection, Google Drive, Google Docs, Notion, and browser; computer use is also coming soon. [seg 1172–1173]

Our users are using Arena's agent mode to perform many long-horizon and complex tasks; many of these sessions have dozens if not hundreds of tool calls. Here is one example I took from our Agent Arena: someone used Arena's agent mode to develop a financial research RAG pipeline, and this particular task involved 84 turns and 676 tool calls. We have millions of agent sessions like this in Arena's agent mode. What this means is that Arena's agent mode becomes an endless source of very high-quality data based on real-world agent use, from which we can harvest and mine important signals and turn them into a reliable agent evaluation product. [seg 1174–1174]

## Methodology: randomized controlled trials

So how exactly do we go from Agent Arena to agent evaluation? The methodology is very simple: we leverage randomized controlled trials, 随机对照实验, which is very similar to A/B testing. When users start an agent session on Arena, we randomly sample an orchestration model from the hundreds of models we have on the platform. Across millions of sessions, we can make sure that each orchestration model is exposed to a representative and comparable distribution of tasks. We then harvest all the traces associated with each orchestration model, mine valuable signals from those traces, and turn them into our evaluation measurement. [seg 1175–1175]

Today we're measuring five important capability-related signals based on agent mode. The first is confirmed success: did the agent successfully complete the task the user asked it to do? The second is praise versus complaint: how much does the user like versus dislike the agent's performance? Steerability: how much does the agent require steering and correction from the user? Bash reliability: how efficiently can the model use bash? And tool hallucination: how much does the model hallucinate about the tools it's using? We leverage a combination of LLM judges and careful human curation to extract the signals from each trace, and we aggregate across these five signals to produce the final capability score for each model. This is how we put together the final evaluation for agents and the agent leaderboard. [seg 1176–1177]

## Ongoing work

I also want to share some of the ongoing work around agent evaluation. First, safety alignment. This is a very important topic: in Silicon Valley, and I'm sure also in China, people nowadays not only talk about how intelligent and capable the models are, but also how safely the models behave and how aligned they are with human values. This is why a month ago we launched the Alignment Index at Arena. The first version of the index measures three important signals. Unauthorized action: does the model do something the user did not authorize it to do? False attribution: does the model attribute an intent to the user that the user does not actually have? And deceptive completion: the model claims that it completed a task when it actually did not. These are the first three signals captured in the Alignment Index, and we happily noticed that Tencent is one of the top-ranked labs based on models' alignment behavior. Right now we're also working on introducing more safety signals into this index, for example harmful compliance, which will make the safety alignment index even more comprehensive in capturing safety- and alignment-related behavior of models. [seg 1186–1187]

We're also working on harness evaluation. Previously I mentioned that the key methodology is randomization over the orchestration model. The next step is that we also want to start randomizing across different harnesses, starting with Claude Code, Codex, Pi and OpenCode, some of the very popular harnesses. Later on we can also allow model labs to bring their own harness into our evaluation product, so we can test the performance of model–harness combinations. [seg 1188–1188]

We're also working on building an agent auto-eval product. We trained a user simulator on the millions of sessions that happened in Arena's agent mode, and now we can use the user simulator to simulate interaction between agent and user. So we don't need to wait for days or even weeks to accumulate the tens of thousands of sessions needed to perform the evaluation; we can use simulation to do an agent eval within a few hours and get a very fast result. Last but not least, Arena is also working on turning some of the agent traces into rubrics and RL environments to help labs with post-training. Eventually we hope to provide a closed-loop flywheel that goes from evals to actionable insights to post-training products, such as rubrics and RL environments, that help labs actually improve the performance of their models. [seg 1189–1189]

## Key takeaways

Some key takeaways from this talk. Agent evaluation requires a very carefully designed system with interchangeable components, trace collection at scale, and robust methodology for signal mining and results computation. Currently, based on Agent Arena, US frontier models are leading the race; Chinese open-weight models are in the second tier and catching up, but there's still a significant gap. [seg 1190–1191]

When deciding which models to use, users should leverage the Pareto curve and Pareto frontier to make intelligent trade-offs between performance, cost, time and token consumption. As for Arena: as mentioned, we are the largest global eval platform based on real-world use cases. Users, developers and enterprises can leverage Arena's agent mode to do real work, and leverage Arena's leaderboards to pick the right models for their use cases. For frontier labs and new labs, which are our customers, if you're in the audience: we can work with you on co-releasing models, co-marketing, and private testing and private evaluation of your model checkpoints before you launch them publicly. And last but not least, we're building post-training data products, such as RL environments, to help these labs improve the performance of their models. [seg 1192–1192]
