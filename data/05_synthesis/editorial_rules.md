# 报告表达规范

供修改本仓库报告的人使用。只读报告可直接看正文；核对本次修改，先看本页前三节，再看全文左右对照。

本轮以提交 `710c35f` 的原报告为底稿。上一轮被否定的文案已归档，不作为新稿的基础。保留已认可的主标题「AIE Shanghai 2026 参会笔记」及独立的代码修复。

## 一、先确认原稿在说什么

原稿的中心判断是：**模型公司与垂直应用双向整合，双方争夺的稀缺资源是垂直领域的长程数据，数据商同时向两方供货。**

这个判断包含四个不可省略的部分：

1. **模型公司上行整合。** 一方面把 harness 功能内化进模型，另一方面推出第一方应用。只写「模型公司做应用」会漏掉前者，也会丢失原稿对产业分工边界变化的判断。
2. **垂直应用与企业下行整合。** 基于开源模型和自有数据做后训练。这里有「开源模型」「自有数据」「后训练」三个条件；不能笼统改成「自己训练模型」。
3. **稀缺的是垂直领域的长程数据。** 泛称「行业数据」或「完整任务数据」都会损失范围或技术含义。原稿说持有此类数据的应用公司自用，不能写成这些应用公司正在向模型公司出售数据。
4. **数据商的客户和风险不同。** Copula 服务模型公司；MindLab 服务行业公司；Arena 和 You.com 的供货关系与主业有不同张力。表格里的差异支撑后面的数据壁垒和剪辑数据判断，不是可以随意删掉的公司清单。

原稿对内容行业进一步提出两点：

- **垂直数据壁垒可被复制（推断）。** 即使应用公司不出售数据，专家数据商仍可能雇用同行专家生产同领域任务。这是对壁垒的判断，不能泛化成「数据也可以由别人做出来」。
- **剪辑数据处于筹备期。** Copula 的现有产品没有剪辑，但在储备剪辑专家；外部已有早期轨迹数据集和 benchmark。需要同时保留「特定供应商的产品阶段」和「外部早期信号」，不能合成「剪辑数据已经产品化」。

原稿后半部分按四个主题展开：实时音视频的模型分工、coding agent 的验证与协作、沙箱与在线存储的职责分离、轨迹和多模态数据的离线处理。每节原本已有结论句，案例是对该结论的展开，不应再被改写成更宽泛的行业口号。

## 二、金字塔结构如何用于这篇报告

### 1. 先建立共同背景，再在各节结论先行

产业版图放在第一节，先让听众知道现场来了哪些公司、它们处在什么业务位置。图前用几行文字说明模型与应用这两条“掘金”路线，以及数据和 Infra 作为“卖水、卖铲子”业务的分工；企业内部落地的公司另说明为使用方。

建立这个共同背景后，再进入双向整合的核心判断。金字塔结构用于各节内部的结论与论据组织，不要求把抽象判断放在听众理解产业参与者之前。

### 2. 以上统下

每一层的概括都必须覆盖下一层实际内容。

- 「双向整合」下分别放上行、下行和长程数据的争夺。
- 「数据供给关系」下保留谁卖给谁、谁只自用，以及各自对主业的影响。
- 「对内容行业的含义」下保留壁垒可复制的推断、剪辑数据的阶段判断及其依据。
- 四个主题各自保留原来的结论、做法和未解决问题。

上层标题不得比下层证据更强，也不因为相邻排列就把并列观察写成因果关系。

### 3. 同类归组

产业整合、数据交易、对内容行业的推断和工程实践分层表达。一个分组只回答一个问题；同级条目沿同一维度展开。

不为了凑齐结构而补充新观点，也不把所有案例压成相同模板。Cookiy 的多模型串联与 Tripo 的程序 / 生成模型分工应分别保留。

### 4. 按逻辑顺序展开

总体顺序：产业版图及业务分工导读 → 中心判断 → 支持观察 → 数据供给与业务影响 → 对内容行业的含义 → 分主题实践 → 局限。

案例内已有的「目标 / 放弃的方案 / 现行方案 / 未解决」和「问题 / 做法 / 能力」各有用途，保留其原有顺序。论证需要的比较对象、替代方案和适用条件不可省略。

## 三、措辞边界

| 项目 | 规范 |
|---|---|
| 主语与对象 | 保留原稿的具体主体。模型公司、垂直应用、企业、数据商、行业专家不互相替换。 |
| 关键术语 | 保留「双向整合」「harness 能力内化」「第一方应用」「后训练」「垂直领域的长程数据」「数据壁垒」「checkpoint」「非共识」「新信息量」等有区分作用的词。 |
| 阶段与语气 | 「筹备期」「目前」「可能」「未解决」「尚未核实」保留原位或跟随原判断移动；不能升级成已经成熟、普遍成立或必然发生。 |
| 事实与推断 | 「（推断）」跟随其对应命题；讲者观点保留「指出 / 认为 / 观察到」及讲者姓名，不能变成整理者已经证实的事实。 |
| 句子 | 可拆长句、补齐指代、调整并列层次；拆句后主语、条件、否定、程度和对比关系都要保留。 |
| 标题 | 使用准确、简短的主题名或结论句；不以删掉专业含义来追求口语化。保留已认可的主标题和「全部演讲」等导航文字。 |
| 案例与来源 | 不增加原稿没有采用的案例；原有案例、引文编号、表格行、数字和未解决问题逐项保留。 |
| 核对 | 对照原稿逐条检查主语、谓语、对象、范围、阶段、推断标记和引文。不能只靠字数变少判断表达变好。 |

## 五、另行处理的原稿问题

核对证据时发现以下表述边界，先保留原稿文字并记录在此，不混入本轮润色：

- OpenClaw 的 adaptive testing：原报告写作「按回归风险挑选要跑的测试」，`sections/s2_evidence.md` 的 B11 引文说明它刚合入、尚未全面启用。若修订阶段状态，应作为事实修订单独确认。
- 实时音视频的总括句含「目前能用的产品都在组合多个模型」。证据分别是 Cookiy 的多模型串联和 Tripo 的程序 / 生成模型分工，外推范围需要单独复核；本轮不将其扩大成普遍定律。
- 证据表包含历史草稿的 keep / drop 建议，不等于所有建议都已进入最终原稿。本轮以原报告实际采用的内容为边界，不据此重新扩充报告。

这些记录不构成第二版新增的行业判断。后续若改事实，需单独说明依据和改动范围。
