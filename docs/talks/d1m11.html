演讲骨架

  1. 智能硬件调用云端 API 有三个硬伤：产品卖得越好 token 成本越高、断网不可用、医疗投资法律等场景的隐私合规；端侧 AI 以即时响应、可用性、隐私和零 token 成本解决。
  2. AutoArk 按算力把硬件分为小、中、大三档，分别提供开源模型：小算力用音视频小模型加 EVA SDK，中算力用可在手机上运行的大参数 MoE 模型，大算力用即将开源的笔记本级多模态 MoE 模型。
  3. 端侧大模型靠 MoE 稀疏激活加 prerouter 参数预加载突破内存墙和解码速度瓶颈。
  4. 案例：与韶音合作的 AI 运动耳机采用端侧加云端混合路由，简单意图全端侧处理，只有开放式问答才调用云端，大幅降低 token 成本。

为什么智能硬件需要端侧 AI

我们首先来看一下第一部分：为什么智能硬件需要端侧 AI？或者说，为什么我们不直接使用云端的 API 呢？相信在座有不少听众自己做过智能硬件或者智能软件的产品，或者 personal agent 的产品。比如说我们在做一款智能眼镜、智能耳机，或者一款软件的时候，通常的做法是：完成这款硬件的开发之后，我们会选择调用云端大厂的 API，无论是音视频模型的 API 还是大语言模型的 API。通过这种方式，能够为我们的产品带来 AI 对话、智能体的一些应用，包括会议纪要、智能转录等各种各样的需求。但是通过这种调用云端 API 的形式，会带来哪些缺点呢？ seg 646–654

首先我们来看一下成本方面。假设我们现在做了一款智能硬件，它非常成功，年销量达到了 100 万台，同时用户的粘性又非常好，每天能够跟 AI 对话、交互 20 次以上。那么根据我们现在能拿到的公开的大厂 API token 成本，我们可以轻松地算出来，一款年销 100 万台的设备，如果每个用户每天交互 20 次，它的年成本可以轻松达到 10 亿元。这就会带来一个非常尴尬的情况：我们的产品销量越高，我们反而越赔钱。这是现在很多做 AI 应用的公司所面临的一个困境。 seg 655–663

第二点是可用性。如果我们一款产品依赖云端 API 的形式来完成，那也就意味着它必须在网络环境稳定的情况下使用。一旦遇到断网和无网的环境，我们整个的核心体验会迅速下降，甚至达到不可用的情况。这对于我们用户体验的延续来说是非常难以接受的。 seg 664–667

第三点是隐私的问题。随着现在 AI 功能在普通消费者这边的渗透率越来越高，我们会发现用户对于隐私的关注也越来越强。当然在日常生活中，咱们跟 AI 进行对话的时候可能觉得还好，但是一旦到了职场，比如说医疗、投资、法律这些场景，我们核心的录音、视频、核心的数据、结论文件等，一旦调用云端 API，也就意味着你的数据会迅速地传递给模型的 provider，从而带来数据的泄露。在这些情况下，如果咱们做的一款产品是专门 target 这些非常专业的工作领域的话，你就会很快遇到合规的问题。 seg 668–674

什么是端侧 AI

那么端侧 AI 就是很好地解决这件事情的一个方法。什么是端侧 AI 呢？我们简单给出一个定义：端侧 AI 指的就是在咱们的硬件本身上，利用这个硬件本体的算力去运行模型，从而完全避免对云端 API 的调用。 seg 675–678

利用端侧 AI 带来的优势是显而易见的。首先就是即时响应：因为我们整个模型是跑在硬件本体上的，这也就意味着我们可以做到所有的 AI 功能毫秒级别的响应，而无需去调用云端的 API，自然也不会受到云端网络波动的影响。其次就是可用性：咱们的产品在无网、弱网的环境下，不需要调用云端模型〔?〕，自然就不会遇到任何体验方面的问题。无论是在高铁、飞机、电梯以及各种弱网、无网的环境，它的 AI 功能体验都可以得以延续。第三点就是隐私，这个很好理解，因为我们所有的核心数据都在设备本身上去处理，核心的隐私数据是不出域的，这自然而然就带来了它的一个优势。最后就是零成本：因为我们的模型不需要调用云端的 API，自然就不会带来任何 token 的成本。 seg 679–688

从行业趋势来看，大家其实也可以发现，现在端侧 AI 已经出现了一个爆发的趋势。一方面，随着模型本身的尺寸、架构和训练方法在持续升级，1B 到 7B 这个规模的模型，它的智力水平也持续进步，基本上已经能够接近前几年旗舰大模型的水平。第二，芯片本身的算力也在加强，有越来越多的嵌入式芯片和手机芯片开始带上 NPU，算力也从零点几个 TOPS 到 1 TOPS、10 TOPS，甚至几百几千 TOPS，这天然为端侧模型的部署和运行创造了非常良好的条件。 seg 689–694

当然，部署端侧模型也不完全是免费的。对于一款智能硬件而言，它天然会受到内存、电量、续航各方面的限制，这阻碍了我们无脑地把最大的模型放到硬件上去。其次就是平台：以前我们做云端模型的时候，通常只需要适配 NVIDIA 的 CUDA 生态，或者像华为这种国产卡的新算力生态就可以了。但是在端侧，我们有各种各样的平台，比如 FreeRTOS、Arm Linux、ESP32、iOS、Android，每一个平台、每一个编程语言都需要重新去写端侧模型的部署逻辑，这对于工程化来说是极大的一个成本。虽然存在这些问题，我们依然认为端侧 AI 是我们接下来发展的一个重心，也是接下来 AI 模型和 AI 产品发展的一个重心。 seg 695–703

中算力设备

第二块叫做中算力设备，指的是手机和平板。这类产品通常会有更高的配置，所以它所需要的是更强的模型智能水平。对于这样形态的产品，我们通常 target 的场景是 Personal Agent 以及手机智能体，就像最近刚刚发布的 Apple Intelligence〔?〕，或者咱们国内的小爱同学等等，都属于这样的场景。这样的场景需要的是更强的模型，能够满足手机上一定复杂度的任务的自动化调用。 seg 746–751

在这一块，我想给大家 demo 一下我们在手机及中算力设备上所提供的端侧模型。大家可以看一下，我们在这一块主打的是 35B 的 MoE 大语言模型。这个模型是完全开源，并且在端侧能运行的。我们通过推理引擎和模型的协同加速，成功实现了在 iPhone 16 Pro 上以最高 2G 的内存即可运行 35B 的 MoE 大模型。大家可以看一下这个录屏的右上角，它是打开飞行模式的，就是完全不调用任何网络，并且整个录屏不做任何加速，是真机录屏的效果。 seg 752–757

通过 35B 的 MoE 大模型，它可以实现远超端侧 4B、8B 和 10B 这种级别模型的智能水平，可以完全满足手机智能体的需求，像一些工作流的调用、phone use、computer use，以及工具和智能体的调用，都完全没有问题。同样，我们这个 MoE 大模型本身也是支持多语言的。我们现在的推理引擎已经完全开源，兼容了 iOS、Android、Windows、Mac 等各种各样的平台，每一个平台上都有对应的开源代码、推理引擎和对应的 App，一键安装 App，即可以离线的形式使用我们的端侧模型。 seg 758–764

大家可能会好奇，一个 35B 的 MoE 大模型怎么可能在端侧这么小的内存跑起来呢？事实上我们在这一块做了非常多的工作。首先在模型这一块，我们主打的是 MoE 大模型。为什么呢？因为 35B 的大模型，它的参数量会远远超过手机和平板的内存，不可能完全放进来。而 MoE 大模型是一个稀疏模型架构，这也就意味着我们在做每一次推理的时候，真正激活的参数只有 3% 到 10%。我们把活跃的参数加载到内存里面，从而能够突破模型部署的内存墙。 seg 765–772

同时，也不是简单地把活跃参数放到内存就可以了。有一个很严重的问题是，MoE 大模型在做每一个 token 解码的时候，下一个 token 和这个 token 所需的参数有可能完全不一样。如果在每一次 token 解码的时候，再把参数从 SSD 加载到内存，整个解码速度会非常慢，有可能会好几秒才吐一个 token，这显然不满足实际使用需求。为了解决这一点，我们也创新性地提出了 prerouter，就是一种参数预加载技术：把一个预训练的模块加载到我们的 LLM 里面去，让 LLM 在每做一个 token 推理的时候，可以实时地去预测下一个 token、下下个 token 和后面几个 token 所需要的专家参数，并且把这些参数通过后台异步的形式加载到内存，从而当我们在解码每一个 token 的时候，相关的参数已经准备好了。通过这种形式，我们能实现数量级的解码速度提升，从而才能达成刚刚大家在录屏里看见的非常惊艳的效果。 seg 773–784

大算力设备

最后来看一下大算力设备。所谓大算力设备，通常指的是咱们的笔记本，比如说带独显的 Windows 笔记本、MacBook Pro、Mac mini、Mac Studio，或者带独显的台式机这样的硬件设备。对于这样的硬件设备，主打的需求就是 Vibe Coding。相信在座有非常多的工程师和产品经理已经开始用 Vibe Coding 去提升自己的工作流、提升自己的效率，但是 token 的成本是一个非常大的问题。 seg 785–789

在这一块，我们也是第一次发布一个 preview：我们即将开源 150B 的端侧 MoE 多模态大模型。它可以实现最低 18 到 24G 的内存占用，在笔记本、台式机和 MacBook 上都可以很好地运行，能够轻松实现超过每秒 1,000 token 的 prefill 速度和超过 100 的解码速度。通过端侧的 Vibe Coding 大模型，你能做什么事情呢？事实上它的智能水平接近 Flash 类模型的水平，可以轻松实现视频制作、软件开发，以及 computer use 调用 Blender 去做 3D 建模。这些场景都可以通过我们的端侧模型，在你自己的笔记本和电脑上去完成，不需要调用云端 API，也不会有任何 token 费用。 seg 790–795

前面大家看到的所有模型和所有推理引擎，我们全部做了开源。我们也非常高兴看到整个开源社区给我们的反馈。目前我们的模型在开源社区的 leaderboard 上，像我们的音频模型已经实现了 top one SOTA 的地位，并且我们多次登顶了 Hugging Face 的 trending 榜单和首页推荐。我们的开源引擎也实现了超过 1,500 万次的下载量。总体来说，我们的目的就是为大家提供全球领先的端侧 AI 模型。我们所有的引擎和模型都开源，所以非常欢迎大家去试用。 seg 796–802
