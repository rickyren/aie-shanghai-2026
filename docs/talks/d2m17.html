演讲骨架

  1. 家庭服务机器人是高度耦合的硬件与软件系统，需要时间戳对齐和不同频率（模型与电机）的平滑衔接。
  2. 核心是 self-evolving WAM：世界动作模型联合生成动作和预期未来，并用 Top-K 并行想象和真机交互数据闭环，不靠人工决策更新时机。
  3. 在叠衣、晾衣、做意面、辣椒炒肉任务上，多轮迭代后成功率明显提升；通用大模型 agent 作 System 2、自己的 WAM/VLA 作 System 1 是下一代架构方向。
  4. 真正的进化要把机器人放进真实家庭，已进入几百户并积累了大量工时。

硬件

首先看一下，一台机器人应该拥有什么样的硬件配置。这是我们最新一代的机器人产品 F2，它目前拥有 1,500 多个零部件、21 个自由度和 22 个传感器。大家看起来可能像是把一些比较通用的机械手臂、机器人的升降、底盘等做了一个组合，但实际上远比这些硬件的单一系统要复杂。seg 3124–3128

举个例子，我们的手臂动起来的时候，在我们的相机、雷达等传感器的视角下，它的位姿会发生比较严重的变化，这对我们的障碍物识别、避障等就有更高的要求。所以机器人整个硬件系统的耦合度非常高。再举一个例子，我们的手臂应该设计多长、多重，在运动过程中会不会涉及整个机身和底盘的稳定性，影不影响重心的前移等等，这就反过来约束了机器人底盘应该怎么设计。另一方面，机器人的模型和关节模组，它们动作和输出的频率是不同的：模型一般工作在 30 Hz 的频率下，电机一般工作在 500 Hz 的频率，它们之间要如何疏通，保证所有输出的动作有一个相对平滑的输出。seg 3129–3139

软件框架

再看一下通用的人形机器人应该有什么样的软件框架和内容。内容很丰富，但核心包括四大部分：云端平台、软件平台、硬件平台，以及工具链的实现。对机器人来讲，各个硬件和软件模块的系统，非常重要的一点是它们能够统一对齐。比如我现在让机器人去拿桌子上的一个杯子，那我相机下看到的水杯位置，是什么时间看到的？我的手臂真实动到那个位置的时候，机器人的身体、其他部位，以及杯子本体是不是已经发生了变化？这些都是非常耦合的情况，所以必须做到硬件和软件之间的同步和时间戳对齐。不管是模型驱动，还是其他控制律，这都是必须做到的前提。seg 3140–3149

Self-evolving WAM

有了这样的基础打通之后，我们要做的是让机器人在真实场景、真实工作过程中持续地自我进化、自我进步，让它的表现、动作输出越来越好，完成任务的成功率、泛化性也越来越高。这就引入了我们今天的核心：self-evolving WAM〔?〕，一个可以持续自我进化的世界动作模型。它的核心，跟大家最近听到的 RSI 的概念有很多相同之处。核心可以理解为两点。seg 3150–3159

WAM 要负责两个问题：第一，我遇到一个新任务的时候，机器人应该怎么考虑、怎么做、怎么输出动作；第二，输出这些动作以后，我的操作对象和物体会发生什么样的变化。这是 WAM 要解决的问题。seg 3160–3165

那自进化要解决的问题是什么？我们如何把已经执行过的动作，甚至想象过但没有执行过的动作保存下来，以及把执行过的动作和真实物理世界发生交互的过程和动作数据保存下来。这些数据就可以用作下一代模型的训练。所以自进化机制的核心是：不要人为参与来决策模型什么时候进步、什么时候更新，而是由一个统一的闭环数据来源，来解决新一代模型训练的养料问题。seg 3166–3172

跟大家分享一下，我们现在的自进化世界动作模型大概采用了 1 万小时的第一人称数据，和 3 万小时的我们一代机和二代机的真机数据。seg 3173–3175

"共享主干的联合生成动作与预期未来"，本质上讲的是这个 WAM 如何工作。可以看到它的信息输入源来自视觉观测，以及机器人本体的状态，比如每一个关节现在工作在什么位置，有没有奇异〔?〕、有没有关节约束，以及我们要实现的任务目标和它接下来要做的事情。还包括很多约束，比如工作空间的约束、手臂长短的约束、能输出的关节力大小的约束等等。当然也包括动作历史，因为我现在要做的事情，一定要跟上一步做的事情有一个非常丝滑的衔接。这就是我们生成动作与预期未来的方式。seg 3176–3183

Top-K 策略与自进化数据

下一项是 Top-K〔?〕 策略，它是在自进化机制里发挥作用的非常关键的核心策略。本质上，我们希望在产出一个任务的同时，模型同步并行地推理出多种工作结果。比如我们下一个指令让它去夹一个东西，或者干一个任务，其实对我们人类来讲也一样，并不是只能有唯一的做法。我可能在大脑里一瞬间想了好几种做法，但最后执行的可能只有其中一种，是因为我们的大脑对刚刚并行想出来的多种做法有了明确的评分：我认为哪种做法耗费的能量最小，哪种做法时间最快，所以会优选出一种做法。seg 3184–3192

这种没有被执行但被想象过的数据，也可以同时保存下来，用于新的学习。这些数据的类型有：一些是成功和有效纠正的数据，可以用作下一轮模型的 post train 等环节，有效地纠正，使模型往正确的方向走。还有一些失败的数据：上一代模型输出的结果在执行过程中最后失败了，失败的数据也可以拿来训练，用于避免模型往失败的方向走，这个过程本质上是偏好学习的过程。当然还有刚刚提到的，我在大脑中同时想象了很多种做法，但最终只执行了其中一种，另外的三种是候选轨迹，这些候选轨迹仍然可以被保存下来做训练。seg 3193–3205

效果

这一套模型最终的效果怎么样呢？我们一共选了四个任务来观测：叠衣服、晾衣服、做意面和辣椒炒肉。我们模型从第一轮的平均任务成功率 45.4% 的起点，到第三十轮迭代——因为它在自我进化——进化完之后，平均任务成功率达到了 86.6%，平均提升了 41.2 个百分点。seg 3206–3212

四个任务里相对成功率低一点的是辣椒炒肉。因为这个任务我们完整地纳入了机器人备菜的环节，不只是炒、不只是烹饪，还包括准备的环节。我们发现很多用户的声音说，如果我都把菜准备好了才让机器人去做，那我为什么要让它做，而不是我自己做呢？所以在辣椒炒肉这个任务中，我们也加入了备菜环节，比如切肉，就是切整个肉片的过程。大家可以想象，在日常切肉过程中，这个动作其实相对比较复杂，因为涉及刀具和肉的来回切割，所以这个任务的成功率相对偏低一点。seg 3213–3223

这里给大家看一下叠衣服和晾衣服任务的示例。在叠衣服和晾衣服的过程中，衣服的形态、状态是快速变化的。如果我们输出的是直接从起点到终点的做法，很明显没办法在实现过程中进行纠正和纠偏。比如我叠的过程中有外部干扰，把衣服拿走了，那它下一步应该怎么做，就要引入刚才说的世界动作模型：它要能看到当前的视觉观测，结合机器人本体的状态，来判断接下来应该做什么，以及这样做了以后会产生什么后果和变化。这种情况下，机器人叠衣服和晾衣服的行为就有更多抗干扰的能力。晾衣服这一块的应用，也是我们目前在整个机器人领域看到成功率做得最高的一项应用。seg 3224–3233

这一块是我们机器人的厨房场景。左边是完整的辣椒炒肉场景，里面包括切辣椒和切肉，尤其是切肉，比切辣椒更有挑战性，整个操作的精细度更高，长程、甚至长尾的环节更多。切肉的成功率从最初的 38.2%，到最后的 68.9%，也有了非常明显的进化提升。seg 3234–3241

做意面这个任务值得一提：今年 8 月份的 WRC 展会上，我们也持续做了演示，从展会早上开始，一直到晚上展会结束，我们都不停地做这个任务。这除了对模型能力有要求，也是对整个机器人可靠性和稳定性的考验。如果没有一个可靠的、可以持久运行的机器人本体，想要支撑这些任务的长时间运行也比较有难度。seg 3242–3245

通用模型带来的系统架构演进

接下来分享通用模型进化带来的系统架构演进。大家可以看右边的一个简单表单，我不知道是否足够清晰。核心想讲的是，在机器人的评测榜单里，目前排在前几项的，全都是以 agent 架构，或者 agent 加 WAM 的架构拿到最高任务成功率的。这给我们的启发是，现有通用大模型能力的成长，给现在具身大脑模型的发展带来了更多的参与角色和作用。当然在左边这个表单里可以看到，在一些比较精细的任务里，我们的 VLA 和一些世界动作模型的执行能力会更强一点。seg 3246–3255

这给我们的启发是，通用大模型能力的提升，可能会在下一代体系设计里参与更多角色。比如我们当下会用到 System 2 和 System 1 的架构：System 2 采用一些更加通用的大模型或者 agent，System 1 可能用我们自己训练的一些自进化世界动作模型，或者 VLA 模型等等。它们的结合，可能让家庭场景中任务的执行度和泛化率有非常明显的提升。这是当下通用模型的发展对我们非常重要的一个启发。当然，它的最底层仍然受限于机器人本体的控制和保护策略，比如关节的限制、输出动作的频率等等。seg 3256–3267

走进真实家庭

最后想说的是，机器人考验的是所有这些任务的执行度，或者说自我进化。自我进化不只体现在模型方面，在整个机器人产品的硬件和设计方面也有非常多的反馈。我们认为只有把机器人长时间推入用户家里去试用、去体验，才能持续地自我进化。我们目前已经把机器人推广到 500 多个家庭里实际使用，累积的工作时长已经超过 5 万个小时。我们认为机器人真的要进化，一定要走这一步。今天的分享就到这里，非常感谢大家，可以后续多多关注我们的工作，谢谢。seg 3268–3274
