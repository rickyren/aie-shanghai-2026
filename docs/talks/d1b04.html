Beyond Reasoning: Building Infrastructure for AI Agents That Act

裴晟 (Robert Pei) · Visa · 2026-11-05 分会场 · 14:41–14:56 · 场次 d1b04 · 偏宣传

Visa 主张智能体商业的关键不是给 agent 发卡，而是用令牌化、限额、可追溯的授权凭证，加上 agent 与商户之间的信任认证，让人类能把花钱的决策安全地交给 agent；Visa Intelligent Commerce 与 Trusted Agent Protocol 正是为此提供的网络层基础设施。

演讲骨架

  1. Personal Agent 兴起后，支付成为刚需，Agent 正从辅助搜索走向真正交易，原有互联网并非为 Agent 设计，商业模式也将重塑。
  2. 早期场景是 vibe coding 等 agent 自主小额付款，决策从基于商品转向基于任务和预算，这是 agentic payment 的实验场。
  3. 要解决的难题包括 agent 身份与信任、意图与授权、商户生态，以及网站拦截 bot 和风控把机器交易当盗刷。
  4. Visa Intelligent Commerce 的思路：令牌化的限额凭证、用户授权控制、Trusted Agent Protocol 与商户可用性评分，并推出 CLI 和微支付方案。

讲者提出的框架

  • Visa Intelligent Commerce 三要点：凭证、控制权、生态信任：凭证用 tokenize 的 scoped token 而非卡号，控制权要匹配用户明确授权并留痕，生态信任靠 agent 认证和商户握手。
  • 自动商务类比自动驾驶分级：agentic commerce 目前像 L3 的 supervised 驾驶，多数场景仍需 human in the loop 确认，逐步出现完全自主场景。

推出 / 提供

  • Visa Intelligent Commerce：让 agent 使用令牌化、限额、可控的 Visa 凭证完成交易的框架。
  • Trusted Agent Protocol：对 agent 认证并让商户与 agent 握手以确认可信。
  • 开发者 CLI 与微支付方案：帮助开发者用 Visa 卡交易的 CLI，以及面向小额交易的微支付方案（后续推出）。

非共识

  • 商户将面临被 agent 评分的新排名逻辑：衡量的不是相关性而是 agent 下单的难易度，评分低 agent 就不来了。
    PageRank 衡量的是 relevance，而这个分衡量的是你的 usability，包括 agent 到你这来容不容易下单。
  • agent 购买决策由基于商品转为基于任务和预算，具体怎么花由 agent 决定，这改变了纠纷和风控的定义。
    这里面的决策并不是一个基于商品的决策，而是一个基于任务的决策，对吧。

信号

  • 市场格局 / 规律Amazon 等闭环平台屏蔽外部 agent，同时自家 shopping agent 通过与 Visa 合作进入开放网络购买站外商品，平台围墙与 open loop 支付正在博弈。
  • 市场格局 / 规律Google UCP、Stripe、Shopify、Visa 等各自推出 agentic commerce 与支付协议，行业处于协议竞争期。
  • 数据信号风控需要识别机器交易的作息、上下文和执行速度，说明交易侧将产生并购买人与 agent 行为区分的数据。
  • 关注的指标关注 agent 对商户的可用性评分（下单难易度），类比 PageRank 的相关性。

大家好。我是 Visa 的裴晟，英文名叫 Robert，在大中华区负责产品。今天我想给大家分享一下智能体时代里面一个比较重要的话题，就是支付。 seg 528–532

从 Personal Agent 到 agentic commerce

我们最近也看到，自从 Personal Agent 出来，支付变成了一个比较刚需的需求。我前两天看到很多人开始在 X 上面 share，用 Grok Bot 帮自己订票，或者买东西。前两天 Musk 转发了一个 video，应该是用 Grok Bot 去全网搜一双球鞋，好像是 Air，帮他找到了以后直接付款。底下可能用的就是我们 Visa 的 credential。 seg 533–538

实际上 Visa 是在去年，大概 2025 年的 5 月份，提出了一个叫 Visa Intelligent Commerce 的概念。当时我们提出的时候，行业里面还是在一个摸索阶段。在过去一年中我们也看到，除了刚才提到的这种 Personal Agent 以外，很多平台、很多应用开始从让 Agent 帮忙做一些辅助的搜索，到现在开始真正地做交易。 seg 539–547

一个例子是我们今年早些时候跟 Amazon 做的一个合作。大家知道 Amazon 是一个闭环系统，有点像我们中国的生态。前两天 Muse 发布的时候，Amazon 就把 Muse 给 block 了，然后前两天好像 Grok Bot 也被 Amazon block 了。Amazon 自己实际上也在 experiment 这个东西，它有一个 shopping agent 叫 Buy for Me。以前 Buy for Me 只是在站内做搜索和下单。它跟 Visa 合作以后，实际上是在 open 的 network 里面：很多商户也许并不在 Amazon 体系里面，但如果这个 Agent 找到一个更好的商品，或者在 Amazon 上面不卖的商品，那么这个 Agent 可以帮用户去买。但问题是，大家在 Amazon 买东西就知道，你的卡是存在 Amazon 的，并没有存在那个商户那边。那么这个 Agent 就需要用这张卡去帮他做支付。这就涉及到我们所谓的 open loop 的支付方式。 seg 548–559

另外一个例子是大家看到的一些 coding agent。我们也看到在这个行业里面，除了刚才提到的 Big Tech 以外，大家开始讨论这个问题：传统的互联网也好，移动互联网也好，实际上不是为 Agent 打造的，对吧。Even today，我们所有的 Personal Agent 实际上是在模仿人，去这些网站里面做搜索、做交互，甚至有的时候直接 emulate 用户的点击去做一些操作，因为这些网站本质上是给用户设计的。 seg 560–565

所以也开始有了一些更适合 Agent 的、我们叫 agentic commerce 的 protocol，比如 Google 的 UCP，包括 Stripe、Shopify，包括 Visa。这里面既有上层的 commerce discovery，包括订单 checkout，也有真正涉及到钱的时候、下了订单以后做支付的 protocol。这是一部分。 seg 566–570

另外一部分，是我们所谓的自动 agentic commerce，就是自动商务。这个自动化目前还没有完全实现，有点像自动驾驶，现在可能还在 L3 的水平，有点像 Tesla 的 supervised 自动驾驶。很多时候需要 human in the loop 确认以后才能支付，但逐渐会有一些场景完全 autonomous。 seg 571–576

最后是商业模式的问题。传统的 commerce 一部分是通过广告，还有一些是引流，这些商业模式在 Agent 时代可能会被重塑。以前大家是从 search 跳到商品页，然后下单，然后商户给回应。今天的 Agent 有它自己的计算逻辑，或者它自己的一些知识体系，当然也衍生出来所谓 optimize for agent 这么一些方式。所以总结一下，整个 commerce 的 ecosystem 现在正在发生天翻地覆的改变，为了能够 accommodate Agent，更好地帮人类做商业。 seg 577–585

早期场景：vibe coding 与 agentic payment

刚才也提到有一些 early adopters。除了 coding agent——在座的很多可能也是 engineer、developer——B2B 也是我们看到的另外一个可能比较适合 agentic commerce 的群体。 seg 586–589

大概半年前比较火的 vibe coding，我相信在座很多人都已经试过了。我举一个简单例子：一个 engineer 晚上睡觉前跟 agent 说，今天晚上你帮我做一个 APP，do whatever you want，我给你一些 prompt 和我的需求，你帮我把这个东西做了。实际上很多时候会碰到 paywall，对吧——可能是一些有版权的图片，或者你的域名，或者一些 digital service。这就是一个典型的我们所谓 autonomous agentic payment 的场景。用户其实并不 care，比如整个 total cost 可能就 20 美金的时候，我并不 care 你在哪买这个图片，但你得把这事给我办了，因为我要去睡觉了，对吧。这时候你不能大半夜让他起来确认一下；再加上我们在 vibe coding 的过程中经常被问"你确认吗，要不要付"，其实就几分钱或者几块钱。 seg 590–599

这就是一个典型的 agent to agent，或者 agent to digital service 的场景。我认为这衍生出来 agentic payment 的一个刚需场景，就是所谓的 agent payment。行业里面也开始形成了一些 protocol，包括所谓的 Machine Payments Protocol。Visa 也在里面，我们也建立了一些基于卡的链路；当然现在还有一些 alternative rail，比如用 stablecoin，或者用 blockchain 去做。 seg 600–606

但不管用什么方式支付，它的核心逻辑是：人类逐渐开始把控制权交给 agent，去做跟钱有关的 decision。This is a big deal。只是这个场景其实是一个小众场景，大部分人并不会去做 vibe coding 或者这种 development，但这实际上是我们的一个实验场。我们可以看出来，这里面的决策并不是一个基于商品的决策，而是一个基于任务的决策，对吧。你会给它一个 budget，但这个 budget 具体怎么用，甚至可能是由 agent 决定的。那么这时候假设它买错了怎么办？买超是不会的，因为我们会做限额；但它如果买错了，或者产生一些纠纷的时候怎么办？这就是我们在 network 里面需要解决的问题。 seg 607–615

智能体支付面临的问题

刚才提到，除了最后的购买行为以外，在 discovery，包括最核心的购买决策这部分，实际上已经开始由 agent 帮我们人类代劳。这里面就面临好几个问题。 seg 616–619

第一个是智能体的身份和信任问题。由企业做的 agent，像最近比较火的 Instinct，或者 Muse、Grok Bot 这些 personal agent，由公司建立的 agent 比较好办，对吧，我们可以找它去担一些责任，就像 robotaxi 一样，平台可以担一些责。但如果是个人的 agent，我自己装一个 harness，用 Hermes〔?〕，或者用 OpenClaw，拿着我的卡出去买东西，如果买错了，或者甚至这个 agent 背后的人本身做了一些恶意的行为，那么我们卡组织怎么和银行、包括商户一起去杜绝这种行为？这是智能体身份和信任的问题。一部分智能体是不可以信任的。 seg 620–627

第二是刚才说的意图和授权的问题。我们的意图会越来越模糊，因为人会越来越懒，agent 会越来越强大。那么我跟它说了这句话，它最后买了东西以后，你不认账怎么办，对吧。这是意图和授权。 seg 628–630

还有就是刚才提到的生态系统的成熟度，包括商户以后是不是也会被拖没〔?〕，对吧——来的都是机器人，买了就走。那我们传统商户所谓的 loyalty 怎么办，积分怎么办，常客的挽留怎么办，这些都是需要解决的问题。 seg 631–634

我就用刚才那个例子：我这个 engineer 晚上睡觉前，把这个任务交给 agent 去做以后，实际上在今天的商业社会会面临几个问题。第一个是能不能通信的问题。比如大家知道 Cloudflare，你到一个网站以后，它可能上来先问你是不是个 bot。如果我的 agent 去的话，它肯定诚实地说我是个 bot，那你连网站的页面都 retrieve 不了，就被 block 了，对吧，那你还做什么 shopping。所以在 infrastructure level，我们需要有一个 tunnel、一个通道，能让 agent——尤其是在白名单里、或者我们认证过的好的智能体——可以进到网站里面。包括刚才提到的智能体认证的问题，包括这个智能体背后的用户是谁，还有商户是否合法，包括怎么去接入。每一笔交易里面都有这些问题。 seg 635–646

包括在我们的生态系统里面，比如这张卡是银行发的，实际上人和机器的交易是不一样的。还是刚才那个例子，比如大半夜我们的银行突然收到好多笔一分钱、两分钱的交易，在传统的信用卡风控模型里面，这肯定是被盗了，对吧。但实际上是因为我们的 engineer 去睡觉了，让 agent 半夜在帮他 build 一个小 app，然后再买图片。这时候我们就要区分出来，这笔交易到底是人发生的，还是机器发生的——人跟机器甚至作息和行为模式都是不一样的。第二，包括它的上下文、它的执行速度，很多以前的风控规则是要改的，否则我们没有办法适应机器时代的这种交易频率和交易 pattern。 seg 647–655

当然反过来，我们可能也需要教育消费者：比如我们下了一个新的 personal agent，它到底能干什么、不能干什么，我能给它授权什么、不能授权什么。这些都是生态系统里面需要去推进、需要解决的问题。 seg 656–657

Visa Intelligent Commerce 的核心思路

围绕这些，给大家简单介绍一下 Visa 提出来的 Intelligent Commerce 的几个核心思路。 seg 658–659

第一，我今天是不可能直接给 agent 发一张卡的，因为 agent 不是一个实体，它背后挂的还是一个人。所以我们每个人手上的账户，银行账户也好，信用卡也好，借记卡也好，怎么能够安全地、有控制地、有效地付给 agent，这是一个核心问题，对吧。我们提出的概念，一个是 tokenize，就是你不会把卡号直接给到智能体；另外，它可能是一个 scoped token，比如它可能今天晚上就失效了，它的上限是多少，这些都是可以控制的。 seg 660–666

第二是控制权的问题。这个 token 拿去消费的时候，一定要匹配用户的意图和他的授权，而且在这个阶段是要明确授权的。在刚开始的时候，因为 human in the loop，每一笔交易用户都需要进行一次确认。之后在一些小额场景里面，可能变成像刚才提到的那种：比如我今天晚上最高 20 块钱，agent 问你确认吗，你确认了以后，我们认为这也是一个明确的授权。 seg 667–671

再次是我们所谓的生态的信任。就是刚才提到的，智能体跟商户之间实际上要有一个 mapping，不是任何智能体在任何商户都是同样的信任 level。所以我们跟行业和生态伙伴一起做了一些工作，包括我们提的 Trusted Agent Protocol。在这里面，一是我们会对 agent 进行认证，二是商户需要有一个 tunnel 能够跟 agent 进行握手，握手以后确认它是一个好的 agent。 seg 672–678

另外我们也对商户做一些 enablement。我们在旧金山有一个合作伙伴，在帮商户打分。这个分你可以想象成当年的 PageRank：PageRank 衡量的是 relevance，而这个分衡量的是你的 usability，包括 agent 到你这来容不容易下单。如果这个 score 很低，你可以想象 agent 可能就不来了。对于整个生态来说，大家还是希望能更好地帮助 agent 做 transaction。这块就是我们提到的 Trusted Agent Protocol 的 mapping。 seg 679–685

最后，在刚才提到的 developer 的 scenario 里面，我们也有一些 CLI 的产品，帮助 developer 更好地用 Visa card 去做交易。同时我们也在研发一些 micro payment 的 solution，因为传统卡基交易的限额〔?〕，做 micro payment 不是很划算，所以我们在这方面有一些新的 solution，之后会推出。 seg 686–690

总结

这个案例我就不讲了。总结一下，最核心的几个问题：一是凭证，我们需要进行控制；二是用户的控制权在这个阶段还是核心，我们需要让用户知情，包括在整个交易链路里面要留痕，这些比较重要；第三是生态。在座的有些公司可能是在做安全的，有一些是在做生态里面商户的 enablement，我们也欢迎大家一起共建这个生态。大家事后还有问题的话，我们在外面有一个 booth，可以到我们的 booth 做更多的讨论。好，谢谢大家。 seg 691–696
