核心判断

模型公司与垂直应用双向整合：模型公司上行，把 harness 能力内化进模型并推出第一方应用；垂直应用与企业下行，基于开源模型和自有数据做后训练。双方争夺的稀缺资源是垂直领域的长程数据，数据商同时向两方供货。

  • 上行。 MiniMax 介绍了内化路径：plan mode 等 harness 功能先成为训练目标，模型掌握后再从产品中移除。投资人戴雨森认为，挤压应用公司的是 Claude Code 等第一方应用。Tripo 的室内场景生成已被 coding agent 直接写代码取代。StepFun 将模型、开源 harness 与托管执行打包销售。d2m08d2m07d2m10d1m09
  • 下行。 Harvey 用内部数据对开源模型做后训练；Langfuse 观察到领先团队用自有标注构建 RL 环境，训练自己的开源模型；Baseten 指出，企业微调开源模型是为了留住客户数据；Techcombank 自建 GPU 部署开源模型。d1b02d1m03d1m06d1m18
  • 稀缺资源。 投资人王淮指出，模型训练数据中金融、出行等垂直领域的长程轨迹严重不足。持有此类数据的应用公司均选择自用，不对外出售。d2m07

分方向

1. 实时音视频

单一实时模型无法同时满足时延、推理深度和状态一致性，目前能用的产品都在组合多个模型。

  • 音视频双工互动（Cookiy，AI 用户访谈） d1b06
    • 目标：实时追问，同时理解受访者的画面和共享屏幕，接收旁听者递来的追问要求
    • 放弃了两种方案：快慢双模型，因为慢模型的结论滞后，还会被快模型带偏；端到端实时模型，因为缺少多路视觉输入、复杂指令遵循和推理能力
    • 现行方案：判断、动作、回复三段子 agent 串联，深度分析放到会后离线复盘
    • 未解决：实时环节的推理深度仍然受时延限制
  • 3D 可交互世界（Tripo EdenLive） d2m10
    • 拆分：程序维护世界状态和规则，输出灰盒画面；生成模型把灰盒画面实时渲染成成品画面
    • 依据：纯生成的世界保持不住状态，程序天然保证一致，而且程序可以由 coding agent 来写
    • 原则：能形式化描述的交给程序，只能靠感知判断的交给模型
    • 未解决：角色离场再回来后外观不一致，对生成结果的控制手段不够，世界运行是否正确也还没有评测方法

2. 大规模 coding agent 的工程实践

agent 的产出已经超过团队的验证能力和协作能力。

  • 典型架构：bot 拉取 issue 后自主提交 PR（Manus）；单人并行运行数百个 agent（OpenClaw）；所有代码和知识放在一个 mono repo 里（Manus）；agent 部署在云端，通过 Slack 调用（Harvey）。d1m13d1m10d1b02
  • 瓶颈一：验证跟不上产出
    • 代码级测试：agent 不停地加测试，CI 成本和 PR 等待时间失控。OpenClaw 的应对是主干 CI 改为定时批量跑，并按回归风险挑选要跑的测试；Data4Life 用变异测试找出 AI 写的作弊测试。d1m10d1b09
    • 交互验证：模拟用户真实使用产品。先由人定义验收标准，再让 agent 通过 computer use 或语义化接口操作产品，生成可验证的结果；人只审核评判标准。代表做法有 OpenClaw、Daily、Instagram。d1m10d2m05d1b05
  • 瓶颈二：多人、多 agent 协作
    • 任务公开：agent 任务对全员可见、可以接管，决策者看到完整上下文后当场决定（Manus）d1m13
    • 共享云端 agent：多人在 Slack 里和同一个 agent 协作，执行记录可以回放成评测集（Harvey）d1b02

3. Agent Infra：沙箱与在线存储

沙箱负责计算，用完可以随时回收；在线存储负责保存状态，让任务能在新的沙箱里恢复。

  • 沙箱：需要有状态、生命周期短、支持高并发
    • Daytona：停用的实例保留在本机，快照预先分发，传输只发增量；它认为在 K8s 上挂网络存储会拉低 IO 和部署密度 d1m12
    • Google：开源的 RL 沙箱，建在 K8s 上，靠预热池和镜像缓存把首条指令做到亚秒级；下一代用快照快速启停，解决沙箱空闲浪费的问题 d1m19
    • 两家对 K8s 的结论相反，但面对的问题一致：冷启动、镜像分发、状态保留、空闲浪费
  • 在线存储（TiDB） d1m17
    • 会话元数据和工作文件独立于沙箱保存，沙箱被回收后，可以在新沙箱里恢复
    • 用 checkpoint 冻结当时的现场，更换模型或 prompt 后从同一现场分叉对比
  • 身份：agent 需要独立的身份，在身份层实施最小权限（Microsoft）。目前还没有落地细节。d1m02

4. 数据 Infra：离线的轨迹与多模态数据

离线侧要解决两件事：从海量 agent 轨迹里提炼出改进信号；让多模态训练数据可以重算、可以追溯版本。

  • Agent 轨迹（Langfuse） d1m03
    • 问题：trace 的量已经超出人工阅读能力，也塞不进 agent 的上下文
    • 做法：先把 trace 压缩成摘要，由小模型按维度总结，再聚类、排序，只把最严重的失败连同完整 trace 交给 coding agent
    • 闭环：后台 agent 持续循环「发现失败 → 编写 eval → 修改 → 回测」，人负责质量标准和发布决策
    • 下一步：用积累下来的标注构建 RL 环境，训练自己的开源模型。Langfuse 已经被列存数据库 ClickHouse 收购
  • 多模态训练数据（LanceDB） d2m18
    • 场景：机器人和多模态训练数据，包括多机位视频、帧、embedding
    • 问题：数据只采集一次，却要反复重算。用对象存储加普通列存的方案，加一列就得重写数据，没有版本管理
    • 能力：加列无需重写，用快照记录每次训练对应的数据版本，单元格级增量计算，多模态数据存在同一张表里
